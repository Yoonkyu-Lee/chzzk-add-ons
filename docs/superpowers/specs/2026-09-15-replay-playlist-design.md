# 다시보기 재생목록 — 설계 문서

작성 2026-09-15 · 상태: 승인됨 · 대상 버전 v1

## 1. 문제

치지직에는 다시보기는 있지만 재생목록이 없다. 결과적으로:

- 정렬은 **최신순과 인기순 둘뿐**이다. 오래된 순 정렬이 없다.
  (`sortType=OLDEST`는 HTTP 200에 빈 배열을 반환한다 — 실측)
- 연속재생은 목록에 쌓인 순서, 즉 **최신에서 과거로 거슬러 가는 방향**으로만 흐른다.
- 한동안 못 본 스트리머의 방송이 쌓이면 이야기를 거꾸로 보게 된다.
- 한 방송이 여러 항목으로 쪼개져 있어 문제가 더 꼬인다. 실측 예:
  오킹TV의 `등갈비`가 `2026-09-13 14:15`(57분)와 `2026-09-13 15:31`(1시간 15분)로
  나뉘어 있고 **제목이 동일하다**. 제목으로는 순서를 알 수 없고 `publishDate`만이 근거다.

## 2. 목표

밀린 다시보기를 **원하는 순서로 이어서 볼 수 있게 한다.** 구체적으로:

1. 다시보기를 골라 담거나, 채널 전체를 오래된 순으로 한 번에 담는다.
2. 담은 순서를 바꾼다.
3. 영상이 끝나면 목록의 다음 항목으로 넘어간다.
4. 어디까지 봤는지 기억한다 — 항목별 재생 위치와 완료 여부.

### 비목표 (v1에서 하지 않음)

- 재생목록 여러 개, 이름 짓기, 채널 섞기 → v2
- 자체 서버, 계정, 기기 간 동기화
- 영상 다운로드, 재생목록 공유 링크
- 클립·채팅 관련 기능, 치지직 UI 재디자인

## 3. 확정된 결정

| # | 결정 | 근거 |
|---|---|---|
| D1 | UI는 **페이지 주입 패널 + Shadow DOM** | 플레이어 옆에서 큐를 보며 조작해야 한다. `documentElement` 직하에 붙여 치지직 리렌더 트리 밖에 두면 SPA 이동에도 살아남고 CSS가 양방향 격리된다. 메시지 통신 계층도 불필요. |
| D2 | 목록 데이터는 **비공식 JSON API 직접 호출** | 인증 없이 200이고 필요한 필드가 전부 온다. DOM 스크래핑은 페이징을 다 돌아야 하고 마크업 변경에 더 약하다. |
| D3 | 전체 담기 기본 순서는 **오래된 순, 같은 날은 시각 순** | 원래 불편했던 지점이다. 담은 뒤 뒤집을 수는 있게 한다. |
| D4 | 저장은 **`chrome.storage.local`** | 용량 제약이 없다. `sync`는 항목당 8KB 제한 때문에 65개 배열을 쪼개야 한다. |
| D5 | 종료 감지는 **`timeupdate`의 남은 시간 기준** | `ended`는 광고·중간 삽입에서 오지 않는 경우가 있어 보조로만 쓴다. |
| D6 | v1의 재생목록은 **딱 하나**, "지금 보는 큐" | 이름 짓기·전환·삭제 UI가 전부 사라져 v1이 가벼워진다. |
| D7 | **Manifest V3 + 바닐라 JS/CSS, 확장 본체는 빌드 없음** | 화면 3개 규모에 번들러는 과하다. 폴더를 그대로 로드해 즉시 테스트한다. 검증용 `puppeteer-core`만 devDependency로 둔다. |

## 4. 정찰로 확인된 사실

추측이 아니라 실제 호출·실행으로 확인한 것만 적는다.

### 4.1 목록 API

```
GET https://api.chzzk.naver.com/service/v1/channels/{channelId}/videos
  ?sortType=LATEST&pagingType=PAGE&page={0..N}&size={n}&publishDateAt=&videoType=REPLAY
```

- 인증·쿠키 없이 **200**.
- 응답: `content.totalCount`, `content.totalPages`, `content.data[]`.
- `sortType`은 `LATEST`, `POPULAR`만 동작. `OLDEST`는 200에 빈 배열.

`content.data[]` 항목에서 쓰는 필드:

| 필드 | 예시 | 쓰임 |
|---|---|---|
| `videoNo` | `15168378` | 시청 URL `/video/15168378`, 큐의 유일 키 |
| `videoTitle` | `어머 개피곤해 진짜` | 목록 표시 |
| `publishDate` | `2026-09-13 01:33:20` | 정렬 기준 (문자열, 초 단위까지) |
| `duration` | `19563` | 정수 초. 총 시간 계산·표시용 |
| `thumbnailImageUrl` | `https://livecloud-thumb…` | 썸네일 |

실측 기준 채널: 오킹TV `0f9a3b4fbb0e7137d1f0b4d70563031c`, 다시보기 65개 / 9페이지.

### 4.2 플레이어

`https://chzzk.naver.com/video/14689850`에서 콘솔 실행 결과:

- `document.querySelector('video')`로 **직접 잡힌다.**
- **`iframe`이 0개** — content script에서 바로 접근 가능하다. frame 분기 불필요.
- `currentSrc`가 `blob:https://chzzk.naver.com/…` → **MSE 기반 스트리밍**(HLS/DASH).
  따라서 `currentTime` 쓰기는 `loadedmetadata` 이후에만 유효하다.
- `video.duration`이 `3582.9344900000124` — **소수점**이다.
  API의 `duration`(정수 초)과 미세하게 다르므로 **완료 판정과 종료 감지는
  플레이어의 `video.duration`을 기준으로 한다.** API 값은 표시·합산용으로만 쓴다.
- `readyState: 4`.

### 4.3 아직 확인하지 못한 것

구현 초기에 puppeteer 하니스로 직접 확인하고 결과를 이 문서에 추가한다.

1. `video.currentTime` 쓰기로 실제 seek이 되는지 (MSE라 되는 것이 정상이나 미확인).
2. 다시보기 목록 페이지의 카드 컨테이너·카드 엘리먼트 셀렉터.
3. SPA 내부 이동 시 `history.pushState` 사용 여부와 URL 변화 시점.
4. 치지직 자체 자동재생이 개입하는 타이밍.
5. 로그인·구독자 전용·성인 인증 영상이 큐에 섞였을 때의 동작.

## 5. 아키텍처

경계의 기준은 **"치지직이 바뀌면 어디가 깨지는가"를 한곳에 몰아넣기**다.

```
manifest.json
src/
  common/
    store.js        chrome.storage.local 읽기/쓰기 — 저장소를 아는 유일한 파일
    queue.js        큐 순수 로직 — DOM·storage·API 무의존
    chzzk-api.js    목록 API 호출 + 응답 정규화 — 외부 스키마를 아는 유일한 파일
    format.js       시간·날짜 포맷
  panel/
    panel.js        Shadow DOM 패널 렌더 + 이벤트 — 치지직 마크업 모름
    panel.css
  content/
    boot.js         진입점: 라우팅 감지 → 페이지 타입별 부착
    videos-page.js  목록 페이지: 툴바 + 카드 담기 버튼
    watch-page.js   영상 페이지: <video> 훅, 진행 저장, 다음 항목 전환
  sw.js             service worker — 아이콘 클릭을 패널 토글 메시지로 전달, 그 이상 없음
test/
  *.test.js         node:test 단위 테스트
  fixtures/         실제 API 응답을 저장한 픽스처
tools/
  harness.js        puppeteer-core 검증 하니스
docs/
  manual-test.md    수동 확인 시나리오
```

### 모듈 경계

각 모듈은 "무엇을 하는가 / 어떻게 쓰는가 / 무엇에 의존하는가"가 한 줄로 답해져야 한다.

| 모듈 | 하는 일 | 의존 |
|---|---|---|
| `queue.js` | 큐 배열을 받아 새 큐 배열을 반환하는 순수 함수 모음 | 없음 |
| `store.js` | 큐/UI 상태의 로드·저장·변경 구독 | `chrome.storage` |
| `chzzk-api.js` | 채널의 전체 다시보기를 정규화된 배열로 반환 | `fetch` |
| `format.js` | 초 → `1시간 23분`, `1:23:45` 등 | 없음 |
| `panel.js` | 큐 상태를 받아 Shadow DOM에 그리고 사용자 의도를 콜백으로 올림 | `panel.css` |
| `videos-page.js` | 목록 페이지 마크업에 툴바·담기 버튼을 얹음 | 치지직 DOM |
| `watch-page.js` | `<video>`에 붙어 진행을 저장하고 다음 항목으로 넘김 | 치지직 DOM |
| `boot.js` | URL을 보고 어느 모듈을 붙일지 결정 | 위 전부 |

치지직 마크업에 의존하는 코드는 `videos-page.js`와 `watch-page.js` **두 파일뿐**이다.
사이트가 개편되면 고칠 곳이 여기로 한정된다.

### manifest 개요

- `manifest_version: 3`
- `permissions`: `storage`
- `host_permissions`: `https://chzzk.naver.com/*`, `https://api.chzzk.naver.com/*`
- `content_scripts`: `https://chzzk.naver.com/*`에 `run_at: document_idle`, ES module 로딩을 위해
  `boot.js`를 클래식 스크립트로 두고 동적 `import()`로 모듈을 끌어온다
  (`web_accessible_resources`에 `src/**` 등록 필요).
- `action`: 아이콘 클릭 → `sw.js`가 활성 탭에 토글 메시지 전송
- 외부 CDN·원격 코드 없음

## 6. 데이터 모델

`chrome.storage.local`에 키 두 개.

```js
// "queue"
{
  version: 1,
  items: [
    {
      videoNo: 15168378,        // number, 유일 키
      title: "어머 개피곤해 진짜",
      channelId: "0f9a3b4f…",
      channelName: "오킹TV",
      publishedAt: "2026-09-13 01:33:20",  // API publishDate 원문
      duration: 19563,          // API 정수 초 — 표시·합산용
      thumb: "https://…",
      progress: 3512,           // 초, 마지막 재생 위치
      done: false,
      unavailable: false        // 삭제·접근 불가 확인 시 true
    }
  ],
  currentIndex: 3               // items 내 위치. 비어 있으면 -1
}

// "ui"
{ panelOpen: true }
```

### 설계 근거

- **`items`를 한 키에 통째로 둔다.** 순서 변경이 원자적으로 끝난다.
  항목별 키로 쪼개면 순서 필드를 따로 관리해야 하고 경쟁 상태가 생긴다.
  항목당 150~200바이트라 65개면 13KB 남짓, `local` 한도(10MB)에 한참 못 미친다.
- **`currentIndex`는 인덱스로 둔다.** 단, 순서 변경·삭제 시 `queue.js`가
  "같은 항목을 계속 가리키도록" 보정한다. 이것이 가장 버그 나기 쉬운 지점이므로
  단위 테스트의 1순위다.
- **`version`** 으로 스키마 마이그레이션 여지를 남긴다. v1에서는 값이 `1`이고,
  읽을 때 `version !== 1`이면 빈 큐로 초기화한 뒤 사용자에게 알린다.

## 7. 기능 상세

### 7.1 담기 (목록 페이지)

주입 툴바에 버튼 셋:

- **전체 담기 · 오래된 순** — 채널의 모든 다시보기를 담는다.
  1. `chzzk-api.js`가 `page=0`을 먼저 받아 `totalPages`를 읽는다.
  2. 남은 페이지를 **동시 3개 제한**으로 순회한다. `size=24`, 65개면 3요청.
  3. 각 항목을 정규화한다. 필수 필드(`videoNo`, `videoTitle`, `publishDate`, `duration`)가
     하나라도 없으면 그 항목을 스킵하고 콘솔에 경고한다.
  4. `queue.js`가 `publishedAt` **오름차순**으로 정렬한다.
     문자열이 `YYYY-MM-DD HH:mm:ss` 고정 폭이므로 문자열 비교로 충분하고,
     같은 날 시각 순서가 자동으로 해결된다.
  5. 이미 큐에 있는 `videoNo`는 건너뛴다. 기존 항목의 `progress`·`done`은 보존한다.
  6. 한 번에 저장한다.
- **골라 담기** — 카드에 체크박스를 띄우는 선택 모드로 전환한다.
- **재생목록 열기 / 닫기** — 패널 토글.

카드마다 좌상단에 담기 버튼을 얹는다. 이미 담긴 항목은 `✓ 담김` 상태로 보이고,
누르면 빠진다.

**카드 부착 실패는 치명적이지 않다.** 셀렉터가 안 맞아 버튼을 못 붙이면
툴바에 경고 배지를 띄우고 "전체 담기"로 우회하게 한다.

### 7.2 패널

`documentElement` 직하의 호스트 엘리먼트 + Shadow DOM(`mode: 'open'`).
치지직 리렌더 트리 밖이라 SPA 이동에도 살아남는다. `panel.css`는 shadow root에
`<style>`로 주입해 양방향 격리한다.

구성:

- 머리: 총 개수, 총 시간, 완료 개수, 진행 바
- 목록: 순번 / 제목 / 날짜·길이 / 부분 시청 진행 바 / 드래그 핸들 / 빼기
  - 현재 항목은 강조
  - 완료 항목은 흐리게
  - **순서 변경은 HTML5 드래그 앤 드롭.** 키보드 접근성을 위해 각 행에
    위·아래 버튼도 함께 둔다.
- 발: `이어서 재생`, `순서 뒤집기`, 큐 비우기

패널은 `store.js`의 변경 구독으로 리렌더한다. 다른 탭에서 큐가 바뀌어도 따라온다.

### 7.3 연속 재생 (영상 페이지)

1. **`<video>` 확보** — `querySelector('video')`. 없으면 `MutationObserver`로
   등장을 기다린다. 플레이어가 늦게 마운트되므로 필수다. 15초 안에 못 찾으면
   연속재생을 비활성하고 패널에 배지를 띄운다.
2. **현재 항목 판정** — URL의 `videoNo`를 큐에서 찾는다.
   - 큐에 있으면 `currentIndex`를 그 위치로 맞춘다.
   - **큐에 없으면 아무것도 하지 않는다.** 일반 시청을 방해하지 않는 것이 원칙이다.
3. **이어보기 복원** — `loadedmetadata` 이후, `progress > 10`이고
   `progress < video.duration - 10`이면 `video.currentTime = progress`.
4. **진행 저장** — `timeupdate`에서 5초 debounce로 `progress`를 기록한다.
   `visibilitychange`와 `pagehide`에서도 마지막 값을 flush한다.
5. **종료 감지** — `timeupdate`에서 `video.duration - video.currentTime < 10`이면
   다음 항목 카드를 띄우고 카운트다운을 시작한다. `ended`도 함께 듣되 보조로만 쓴다.
   사용자가 취소하면 이번 영상에서는 다시 띄우지 않는다.
6. **완료 표시** — `video.currentTime / video.duration >= 0.95`이면 `done: true`.
   판정 기준은 API의 `duration`이 아니라 **`video.duration`** 이다 (4.2 참고).
7. **전환** — `location.assign('/video/' + nextVideoNo)`.
   SPA 라우팅을 흉내내지 않고 전체 로드한다. 느리지만 확실하고,
   상태는 storage에 있으니 잃을 것이 없다.
   다음 항목은 **`currentIndex` 이후**에서 `done`도 `unavailable`도 아닌 첫 항목이다.
   `currentIndex` 앞쪽으로 되돌아가지 않는다 — 되돌아가면 무한 순환이 생긴다.
8. **마지막 항목** — 다음 항목이 없으면 전환하지 않는다. 패널에
   `재생목록을 끝까지 봤습니다`를 띄우고 `currentIndex`는 그대로 둔다.
   사용자가 순서를 다시 바꾸거나 항목을 더 담을 수 있어야 한다.
9. **치지직 자체 자동재생과의 충돌** — 우리가 종료 10초 전에 먼저 개입하므로
   대체로 이긴다. 하니스로 실제 타이밍을 확인하고, 밀리면 치지직 자동재생을
   끄도록 안내하는 문구를 패널에 둔다.

### 7.4 라우팅 감지

`boot.js`가 `history.pushState`와 `replaceState`를 감싸고 `popstate`를 듣는다.
URL이 바뀌면 현재 부착 모듈을 정리(`cleanup()`)하고 새 페이지 타입 모듈을 붙인다.
패널 자체는 유지한다.

페이지 타입 판정:

- `/{channelId}/videos` → `videos-page.js`
- `/video/{videoNo}` → `watch-page.js`
- 그 외 → 패널만

## 8. 에러 처리

조용히 실패하는 경로를 만들지 않는다. 모든 실패는 패널에 보인다.

| 상황 | 처리 |
|---|---|
| API 요청 실패 | 패널에 `다시보기 목록을 가져오지 못했습니다` + 재시도 버튼. 1회 자동 재시도 후 표시 |
| API 응답 스키마 변경 | 필수 필드 검증 → 해당 항목만 스킵 + 콘솔 경고. 전부 비면 위와 동일 |
| 카드 셀렉터 불일치 | 툴바에 경고 배지. 전체 담기로 우회 가능 |
| `<video>` 15초 내 못 찾음 | 연속재생만 비활성 + 패널 배지. 큐 기능은 계속 동작 |
| 삭제·접근 불가 영상 | `unavailable: true` 표시 후 다음 항목으로 진행 |
| storage 스키마 버전 불일치 | 빈 큐로 초기화 + 패널에 알림 |
| storage 쓰기 실패 | 콘솔 경고 + 패널에 `저장하지 못했습니다` 표시 |

사용자에게 보이는 문구는 무엇이 잘못됐고 무엇을 하면 되는지를 말한다. 사과하지 않는다.

## 9. 테스트

### 9.1 단위 테스트 — Node 내장 `node:test`

빌드가 없으니 러너도 붙이지 않는다. `node --test`로 순수 모듈만 검사한다.
의존성 0개.

`queue.js`:

- **정렬**: 등갈비 14:15/15:31 실제 픽스처로 같은 날 시각 순서 검증
- **`currentIndex` 보존**: 순서를 바꾸거나 항목을 뺀 뒤에도 같은 항목을 가리키는가
  ← 최우선. 이 기능의 가장 깨지기 쉬운 지점이다
- **중복 담기**: 같은 `videoNo`를 다시 담아도 늘지 않고, 기존 `progress`·`done`이 보존되는가
- **다음 항목 계산**: 마지막 항목일 때 `null`, `done`·`unavailable` 항목 스킵
- **완료 판정**: 경계값 0.94 / 0.95 / 1.0
- **빈 큐**: 모든 함수가 빈 배열에서 터지지 않는가

`chzzk-api.js` 정규화 함수:

- 실제 API 응답 픽스처 → 내부 모델 변환
- 필수 필드 누락 항목 스킵
- `totalPages`에 따른 페이지 순회 계산

`format.js`: 0초, 59초, 1시간 정각, 12시간 51분 등 경계값

### 9.2 통합 검증 — puppeteer 하니스

`tools/harness.js`가 `puppeteer-core`로 **설치된 Chrome**을 띄운다
(Chromium 다운로드 없음). 확장을 `--load-extension`으로 올린 전용 프로필로
실행하고 chzzk를 직접 방문한다.

확인 시나리오:

1. 목록 페이지에서 툴바가 주입되는가, 카드 버튼이 붙는가
2. 전체 담기 → 큐가 오래된 순으로 채워지는가 (`storage.local` 직접 확인)
3. 패널이 열리고 순서 변경이 저장되는가
4. **새로고침 후 큐와 패널 상태가 복원되는가**
5. **SPA 내부 이동 후에도 패널이 살아 있는가** (D1의 핵심 가정 검증)
6. 영상 페이지에서 `<video>`를 잡고 `currentTime` 쓰기로 seek이 되는가 (4.3-1 확인)
7. 종료 10초 전 다음 항목 카드가 뜨고 전환되는가
   — 긴 영상을 기다릴 수 없으므로 `currentTime`을 끝 근처로 밀어 유발한다
8. 이어보기: seek → 새로고침 → 그 위치로 복원되는가

### 하니스 요구사항

재개 가능성과 안전을 위해 하니스 자체가 만족해야 하는 조건이다.
운영 규칙의 근거는 `CLAUDE.md`의 "하니스 운영 규칙"에 있다.

- **CLI**: `node tools/harness.js [--scenario N] [--headful]`.
  시나리오 단위 실행이 가능해야 한다. 하나를 고치려고 여덟 개를 다 돌리지 않는다.
- **타임아웃**: 시나리오별 하드 타임아웃 60초. 초과하면 실패로 기록하고 다음으로
  넘어간다. 전체 실행에도 상한을 둔다. 멈춘 채로 세션을 태우는 것이 최악의 실패다.
- **프로필**: `tools/.profile/`을 `--user-data-dir`로 고정한다. 임시 디렉터리를
  매번 만들면 중단된 실행이 쓰레기를 남긴다.
- **프로세스 안전**: 사람이 쓰는 Chrome이 같은 PC에 떠 있다. 이름 기준 종료
  (`Stop-Process chrome`)는 금지다. 프로필 경로로 식별한 프로세스만 정리하고,
  puppeteer 브라우저는 `try/finally`에서 반드시 닫는다.
- **결과 출력**: `tools/out/result.json`에 시나리오 번호, 통과 여부, 소요 시간,
  실패 사유, 스크린샷 경로를 기계가 읽을 형태로 쓴다. 이 파일을 근거로
  `docs/progress.md`의 검증 표를 채운다. 로그를 눈으로 훑어 판단하지 않는다.
- **API 호출 절약**: 실제 목록 API를 쓰는 시나리오는 2번 하나로 한정한다.
  나머지는 `storage.local`에 큐를 직접 심어 시작한다. 목록 응답은
  `test/fixtures/`에 저장해 단위 테스트에서 재사용한다.
- **로그인 불필요**: 공개 다시보기로만 검증한다. 로그인이 필요해지면 멈추고 보고한다.

실패 시 스크린샷과 콘솔 로그를 `tools/out/`에 남긴다. 이 디렉터리와
`tools/.profile/`은 커밋하지 않는다. 따라서 **스크린샷은 증빙으로 남지 않는다** —
통과의 증빙은 `docs/progress.md` 검증 표에 적힌 확인 시각과 커밋 SHA다.
그 SHA 이후 `src/`가 바뀌면 그 통과는 무효로 보고 다시 돌린다.

## 11. 남은 리스크

- **비공식 API 의존.** 언제든 바뀔 수 있다. 실패 시 사용자에게 보이는 메시지를
  처음부터 넣고, 파싱 책임을 `chzzk-api.js` 한 파일에 격리해 둔다.
- **치지직 마크업 의존.** `videos-page.js`의 카드 셀렉터가 가장 약하다.
  깨져도 전체 담기로 우회되도록 설계했다.
- **치지직 자체 자동재생과의 경쟁.** 타이밍은 하니스로 확인해야 한다.
- **긴 영상 실사용 검증의 한계.** 12시간 영상을 실제로 끝까지 볼 수는 없으므로
  `currentTime` 조작으로 대체한다. 실제 재생과 다를 여지가 남는다.
