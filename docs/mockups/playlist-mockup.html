밀린 다시보기를
순서대로 몰아보기

치지직에는 다시보기는 있지만 재생목록이 없다. 정렬은 최신순과 인기순 둘뿐이고, 연속재생은 목록에 쌓인 순서 — 즉 최신에서 과거로 거슬러 가는 방향 — 으로만 흐른다. 이 확장은 다시보기를 골라 담고, 원하는 순서로 이어보고, 어디까지 봤는지 기억한다.

02

다시보기 목록에서 담기

기존 다시보기 페이지 위에 툴바 한 줄과 카드마다 담기 버튼이 붙는다. 한 개씩 고를 수도 있고, 채널 전체를 오래된 순으로 한 번에 담을 수도 있다. 후자가 실제로 가장 많이 쓰일 동작이다.

05

어디까지 만들까

v1은 "밀린 방송을 순서대로 본다"는 한 가지 일만 제대로 하는 걸 목표로 잡았다. 나머지는 v1이 실제로 쓸 만한지 확인한 다음에.

v1 — 핵심

이번에 만들 것
  • 채널 전체 담기 (오래된 순 자동 정렬)
  • 개별 담기 / 빼기
  • 순서 바꾸기 (드래그)
  • 연속 재생 — 끝나면 다음으로
  • 이어보기 — 항목별 재생 위치 기억
  • 시청 완료 표시

v2 — 편해지는 것

v1이 쓸 만하다고 확인되면
  • 재생목록 여러 개 / 이름 짓기
  • 여러 채널 섞기
  • "안 본 것만" 필터
  • 목록 내보내기 / 불러오기
  • 구간 건너뛰기 (시작 n분)

안 만들 것

YAGNI
  • 자체 서버 · 계정
  • 영상 다운로드
  • 재생목록 공유 링크
  • 클립 · 채팅 관련 기능
  • 치지직 UI 전면 재디자인
06

회의에서 정할 것

●로 표시한 쪽이 내 추천이다. 이유까지 붙여 뒀으니 반대되는 쪽이 있으면 그걸 짚어 주면 된다.

Q1

재생목록 UI를 어디에 띄울까?

  • 치지직 페이지에 주입한 패널추천 — 목록과 플레이어 옆에 같이 보여야 쓸모가 있다. 팝업은 클릭하면 사라져서 순서 바꾸기에 최악.
  • 확장 아이콘 팝업 — 만들기 쉽지만 포커스 잃으면 닫힌다
  • 크롬 사이드패널 API — 안 닫히고 깔끔하지만 페이지 DOM과 통신이 한 겹 더 필요
Q2

목록 데이터를 어떻게 가져올까?

  • 비공식 JSON API 직접 호출추천 — 인증 없이 200, 제목·시각·길이·videoNo가 전부 온다. 65개를 9번 요청으로 다 받아 정렬 가능.
  • 페이지 DOM 스크래핑 — 스크롤/페이징을 다 돌아야 하고 마크업 변경에 더 약하다
  • 둘 다 (API 우선, 실패 시 DOM) — 코드가 두 배, v1에는 과하다
Q3

"전체 담기"의 기본 순서는?

  • 오래된 순, 같은 날은 시각 순추천 — 원래 불편했던 지점이 이것이다. 담은 뒤에 뒤집을 수는 있게.
  • 치지직 목록 순서(최신순) 그대로 담고 사용자가 정렬
Q4

저장은 어디에?

  • chrome.storage.local추천 — 용량 걱정 없음. 65개 × 여러 목록도 넉넉하다.
  • chrome.storage.sync — 기기 간 동기화는 좋지만 항목당 8KB / 전체 100KB 제한에 금방 걸린다
  • local에 두고 내보내기/불러오기를 v2에 — 동기화 욕심을 파일로 대체
Q5

영상 종료 → 다음 항목 전환을 어떻게?

  • <video>의 timeupdate로 끝 감지 후 URL 이동추천 — ended는 광고·중간 삽입 때 안 오는 경우가 있어 남은 시간 기준이 더 안전하다.
  • 치지직 자체 자동재생을 가로채서 다음 대상만 바꾸기 — 내부 구현에 강하게 의존
  • 새 탭에서 순차 재생 — 사용자 경험이 나쁘다

확인 필요플레이어 DOM과 SPA 라우팅은 아직 실제로 못 봤다. 여기만 먼저 짧게 찔러 보고 시작하는 게 안전하다.

Q6

v1에서 재생목록은 몇 개?

  • 딱 하나 — "지금 보는 큐"추천 — 이름 짓기·전환·삭제 UI가 전부 사라져서 v1이 훨씬 가벼워진다. 여러 개는 v2.
  • 처음부터 여러 개 — 유연하지만 만들 화면이 두 배
Q7

어떻게 만들까 — 빌드 도구

  • Manifest V3 + 바닐라 JS/CSS, 빌드 없음추천 — 폴더를 그대로 "압축해제된 확장 프로그램"으로 로드해서 바로 테스트. 화면 3개짜리에 번들러는 과하다.
  • Vite + TypeScript — 타입 안전과 HMR을 얻지만 셋업·설정이 선행된다
  • Vite + React — 패널이 커지면 값어치가 생기지만 v1 규모에는 무겁다

같은 날 쪼개짐
한 방송이 여러 항목으로 나뉜다. 예: 등갈비 09-13 14:15(57분) + 15:31(1시간 15분). 제목이 같아서 제목만으로는 순서를 알 수 없고 publishDate가 유일한 근거다.
남은 리스크

미확인로그인·구독자 전용·성인 인증 영상이 큐에 섞였을 때의 동작.
